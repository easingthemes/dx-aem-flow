<SectionHeading

  subtitle="Mechanisms that capture signals during execution. Most are per-session and lose memory between runs."

<Section>
  <div class="grid grid-cols-1 md:grid-cols-2 gap-6">
    <ContentCard icon="mdi:wrench" iconColor="bg-emerald-600" title="Self-Healing Loop">
      <strong>Scope:</strong> Per-session, per-step.
      dx-step-fix recovers from failures during execution (targeted fix + root cause escalation).
      Memory is lost after the session ends -- each run starts fresh.
    </ContentCard>

    <ContentCard icon="mdi:magnify" iconColor="bg-amber-500" title="Review-Fix Loop">
      <strong>Scope:</strong> Per-session, per-story.
      dx-step-verify runs up to 3 review-fix cycles. Same issues may recur across stories
      because findings are not persisted.
    </ContentCard>

    <ContentCard icon="mdi:shield" iconColor="bg-red-500" title="Policy Gate">
      <strong>Scope:</strong> Global, static.
      <code>pipeline-policy.yaml</code> restricts what each agent role can do.
      Manually maintained -- human updates after incidents.
    </ContentCard>

    <ContentCard icon="mdi:file-document" iconColor="bg-emerald-600" title="Shared Rules">
      <strong>Scope:</strong> Project-wide, git-tracked.
      <code>.ai/rules/</code> files read by dx skills and automation agents.
      Manual only -- no automated discovery or suggestion.
    </ContentCard>
  </div>

  <HighlightBox severity="info" title="Across runs">
    Only fix patterns carry over between runs -- see Fix Pattern Promotion below.
  </HighlightBox>
</Section>

<Section>
  <PipelineBlock
    label="Promotion Flow"
    description="dx-step-all checks after every logged fix attempt, and once more at the end of the run."
    steps={[
      { title: 'Fix attempt', subtitle: 'fixes.jsonl', color: '#6b7280' },
      { title: '3+ successes', subtitle: '0 failures\nsame error + fix', color: '#d97706' },
      { title: 'Rule written', subtitle: '.claude/rules/\nlearned-fix-*.md', color: '#059669' },
    ]}
  />

  <div class="grid grid-cols-1 md:grid-cols-2 gap-6 mt-6">
    <ContentCard icon="mdi:star" iconColor="bg-brand-700" title="How rules are used">
      Claude Code auto-loads <code>.claude/rules/</code> on every run. <code>dx-step-all</code> also reads
      <code>learned-fix-&#42;.md</code> before its loop and passes the patterns to the step skills, so
      Copilot CLI (which does not load <code>.claude/rules/</code>) gets them too.
    </ContentCard>

    <ContentCard icon="mdi:bug" iconColor="bg-amber-500" title="Bug notes">
      <code>dx-bug-all</code> prints a note when a component has 3+ entries in <code>bugs.jsonl</code>
      (hotspot), or when the root cause matches an <code>error_type</code> already in <code>fixes.jsonl</code>.
      Notes only -- no files are written.
    </ContentCard>
  </div>

  <HighlightBox severity="info" title="Review the rules">
    Promotion is automatic. Rules land in <code>.claude/rules/</code> like any other file -- review them in the
    diff before committing, and delete one that turns out wrong.
  </HighlightBox>
</Section>
