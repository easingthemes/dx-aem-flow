## Net effect on the orchestrator

Before: 5 inner-loop skills (`dx-req`, `dx-plan`, `dx-plan-validate`, `dx-plan-resolve`, `dx-step-all`, `dx-pr-commit`) ran in main context. Per-phase tables, file diffs, parallel-research dispatches, and ultrathink reasoning all entered the orchestrator's window.

After: All 6 of those skills are forked. They write their canonical outputs to `$SPEC_DIR/*.md` files and emit only a `## Return` block to the orchestrator. The orchestrator reads the files on demand (Phase 2 reads `validation-report.md` only when verdict is `fail`; Phase 3 reads `dev-all-progress.md` to summarize step counts; etc.).

The orchestrator itself was already largely status-table-once (per-phase narration was always single `Print:` lines), but the new `### Status-table-once` subsection makes that policy explicit and adds 3 anti-patterns to prevent regression. The `no-source-reads` hook adds a soft guardrail against future authors who try to `Read` a source/rule file from inside the orchestrator.

## Verification checklist (smoke-run acceptance)

These are the things to empirically confirm when you run `/dx-agent-all <ticket>` on a consumer repo. Synthesized from Tasks 3-8 smoke-run steps + the final reviewer's risk list.

### High-priority (the high-risk fork)

- [ ] **Phase 3 progress remains visible.** Tail `.ai/specs/<ticket>-*/dev-all-progress.md` in a second terminal during execution. Each step transition (start → done | failed | healing) must update the file in real time, not in batch at the end. If updates batch, user-visible progress regresses — **abort and revert commit `6193c17`**.
- [ ] **No per-step diff in main context during Phase 3.** The orchestrator should NOT echo step diffs, mvn output, or fix-loop chatter into chat. Only one-line phase summaries.
- [ ] **Phase 3 final summary derives from the file.** After `dx-step-all` returns, the orchestrator should print one line like `Phase 3: Execution — N/N steps done; M heal cycles`, generated by the `grep -c` recipe in `dx-agent-all:Phase 3` — not a quoted dev-all-progress.md table.

### Medium-priority (other fork sites)

- [ ] **Phase 1 prints no inline file content.** No `explain.md`, `research.md`, or `share-plan.md` body should appear in chat. Only file paths.
- [ ] **Phase 2 dx-plan does not echo extended thinking.** Confirm `plan-thinking.md` exists in spec dir and has substantive content. The chat output should be a single line + the Return block.
- [ ] **Phase 2 dx-plan-validate verdict drives correct branching.** Try a ticket where validation flags issues (or hand-edit `implement.md` to break a requirement-coverage check) and confirm:
  - `verdict: pass` → continues to Phase 2.5
  - `verdict: warn` → continues OR triggers `/dx-plan-resolve` based on interactive choice
  - `verdict: fail` → triggers `/dx-plan-resolve` and re-validates; STOPs if still fail
- [ ] **Phase 5a dx-pr-commit commits cleanly under fork.** Confirm the commit lands and the orchestrator emits only the verdict line + commit SHA reference, not the full git diff.

### Policy enforcement (Tasks 9-10)

- [ ] **Pipeline Phase Status table emits only at Final Summary.** Run `/dx-agent-all`, watch all phase boundaries — table appears exactly once.
- [ ] **Mid-run recap doesn't re-emit the table.** Ask the orchestrator "status" or "where are we" mid-run. It should print a one-line summary derived from `dev-all-progress.md`, not requote the prior status table.
- [ ] **`no-source-reads` hook fires.** Manually trigger a violation: ask the orchestrator to read a `.java` file or `.claude/rules/be-htl.md` while it's running. Stderr should show `WARN: dx-agent-all is reading <path>...`. The read should still proceed (this is informational, not blocking).
